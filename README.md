# Engineering Knowledge Base

A structured engineering knowledge base for documenting **durable, reusable technical knowledge** across software engineering, data engineering, AI, cloud, IoT, and related engineering disciplines.

The purpose of this repository is to build a long-term technical reference containing concepts, principles, patterns, practical examples, and engineering practices that are worth understanding and reusing.

---

## Purpose

This repository is **not a course notebook or learning diary**.

It exists to capture knowledge that remains useful beyond a specific course, tutorial, or project.

Examples include:

* Engineering concepts
* Technical principles
* Reusable patterns
* Architecture concepts
* Command references
* Development practices
* Common pitfalls
* Technical comparisons
* Short practical examples
* Lessons that generalise across projects

The goal is **quality and long-term usefulness rather than volume**.

## Repository vs Wiki

The repository and GitHub Wiki serve different purposes.

### Repository

The repository contains **durable engineering knowledge** that benefits from version control, structure, history, and long-term maintenance.

Examples:

* Python concepts
* SQL concepts
* Data engineering principles
* Git/GitHub concepts
* Architecture patterns
* Engineering practices
* Reusable technical examples

### Wiki

The Wiki is intended primarily for **quick-reference and environment/setup information**.

Examples:

* VS Code installation and setup
* Python environment setup
* Git configuration
* Keyboard shortcuts
* Command cheat sheets
* Development environment configuration
* Quick-reference guides

The Wiki should remain lightweight and practical rather than becoming a second documentation repository.

## Learning and Project Workflow

The knowledge base is part of a broader engineering learning workflow:

```text
Learn
  ↓
Practice
  ↓
Build
  ↓
Document Durable Knowledge
  ↓
Anki Recall
  ↓
Apply
```

Not everything learned needs to be documented.

A course exercise does not automatically belong in this repository.

A concept should be documented when it is important enough to become part of the engineer's reusable knowledge.

---

## Relationship With Projects

Knowledge and implementation are deliberately separated.

### Engineering Knowledge Base

**What is the engineering concept?**

### Project Repository

**How is the concept applied to solve a real problem?**

For example:

```text
Python Knowledge
      │
      ▼
Learn functions
      │
      ▼
Practice
      │
      ▼
Expense Tracker
      │
      ▼
Apply functions in a real system
```

The KBA explains the general concept.

The project demonstrates its practical application.

## Documentation Principles

Knowledge documented here should generally be:

* Accurate
* Clear
* Concise
* Reusable
* Practical
* Easy to navigate
* Focused on understanding
* Independent of a single project where possible

Where useful, documentation should answer:

1. **What is it?**
2. **Why does it matter?**
3. **How does it work?**
4. **When should it be used?**
5. **What are the common mistakes?**
6. **What are the relevant trade-offs?**
